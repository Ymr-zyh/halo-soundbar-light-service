# 适配其他花再 / EDIFIER 型号

本指南面向希望使用 AI 辅助修改自己 fork 的用户。当新设备与 Halo Soundbar Max 使用同一协议时，适配可能只需替换身份和少量协议常量；如果帧头、查询命令、状态分包或开关载荷不同，则必须修改协议层并重新完成真机验收，不能视为“换一个 VID/PID”。

## 首先理解安全边界

项目故意严格锁定一个已验证设备。写入前同时检查 VID、PID、interface、usage page、usage、产品名称与状态协议，并且只允许两个固定的电源开关写入。

适配时应保留这些原则：

- 不要删除产品名称、interface 或 usage 检查，也不要改成“选择第一个 VID/PID 匹配设备”。
- 不要为了让探测通过而忽略未知帧、非零填充、缺包或状态结构错误。
- 未确认命令格式前只做枚举、抓包和状态读取，不运行 `off` / `on`。
- 未完成可恢复的 `off → on` 往返前，不安装服务，不测试真实关机。
- 只允许修改已证明是灯光电源开关的字节；不提供任意命令、任意索引或原始报文写入入口。

## 需要先收集的证据

请在修改代码前准备以下信息。发布 issue 或把资料交给 AI 前，删除 HID path、序列号、Windows 用户名与本机绝对路径。

1. 准确型号、官方软件版本和音箱固件版本。
2. Windows 设备管理器中的 VID/PID。
3. `hidapi` 枚举结果中的 `interface_number`、`usage_page`、`usage` 和 `product_string`。
4. 官方 TempoHub 仅执行“关灯”一次和“开灯”一次时的 USBPcap/Wireshark 抓包。抓取时不要同时改颜色、效果、亮度或速度。
5. 每次操作前后的完整 64 字节报文，标明主机到设备和设备到主机的方向。
6. 如果已知只读查询命令，保存多次查询的响应，以确定分包数、灯组编号、开关索引和开关值。

抓包只能证明当时官方软件的行为。如果同一型号有多个固件版本，应将固件范围记录为适配前提，不要假设所有批次必然相同。

## 通常需要修改的位置

| 文件 | 作用 | 适配时的检查点 |
| --- | --- | --- |
| `src/halo_soundbar_service/device.py` | HID 枚举与严格身份匹配 | `_IDENTITY` 中的 VID、PID、interface、usage page、usage、产品名称；`enumerate()` 使用的 VID/PID |
| `src/halo_soundbar_service/protocol.py` | 帧构造、响应解析和状态分包 | `REPORT_ID`、帧头、查询命令、响应帧头、灯组 `ARRAY_INDEX`、`PowerTarget`、载荷格式、长度/校验/填充规则 |
| `src/halo_soundbar_service/controller.py` | 写入前后状态验证 | `_validate_snapshot()` 期望的灯组、开关条目、开关值和样式指纹范围 |
| `src/halo_soundbar_service/cli.py` | 诊断输出 | `probe` 输出中的设备身份与控制目标名称 |
| `tests/fakes.py` 与 `tests/test_*.py` | 安全回归保护 | 身份 fixture、真实响应字节、固定开关帧、非目标设备拒绝、样式不变性 |
| `README.md` 与验证文档 | 用户边界与实测证据 | 明确新型号、固件、已验证字节、未验证假设与最终 EXE 摘要 |

如果新设备只是身份字段不同，AI 也必须用抓包 fixture 证明查询和四条开关帧与原型号一致。没有这些证据时，不应把变更归类为“仅修改身份”。

## 建议的适配顺序

1. fork 项目并新建功能分支；不要在已安装的服务目录中直接修改文件。
2. 让 AI 阅读本指南、设计文档、实现和现有测试，再根据枚举/抓包证据写出适配设计。
3. 先添加会失败的测试：真实响应 fixture、四条开关帧、严格身份匹配和错误设备拒绝。
4. 实现最小修改，运行全套单元测试。测试不应访问真实 HID、SCM 或执行关机。
5. 构建 EXE 后首先运行只读 `probe`。必须确认只有唯一目标接口，设备身份、灯组、效果和开关条目全部符合证据。
6. 保存完整状态与样式指纹，再手动执行一次 `off`，立即读回验证。任何异常都停止后续写入。
7. 立即执行 `on` 恢复灯光，再次读回。比较三份完整快照，必须只有已证明的开关字节变化。
8. 只有交互命令和恢复路径都成功后才安装服务；先验证启动开灯和等效 PRESHUTDOWN，真实关机仍需单独人工授权。
9. 在验证文档记录代码提交、EXE SHA-256、设备/固件范围、测试数量、抓包来源、开关往返和样式对比结果。

## 什么情况下不是“少量修改”

出现以下任一情况时，应把适配视为新的协议实现，重新做设计和完整验收：

- 查询命令不是 `0x6A`，或开关命令不是 `0x6B`。
- 主机/设备帧头、长度字段、校验规则或 Report ID 不同。
- 状态不是两个 `0xE3` 分包，或每条记录不是现有的六字节结构。
- 开关不是独立条目，或开关操作会同时改变颜色、效果、亮度或速度。
- 设备需要加密、配对、会话令牌、固件升级或其他持久状态变更。

这些情况下，不要让 AI 通过“兼容所有报文”或“失败时仍继续写入”来勉强运行。安全的结果应该是拒绝写入并要求更多证据。
